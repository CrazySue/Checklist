## 🏗️ Обзор архитектуры

### 🧱 Структура одного файла

Приложение — это **один HTML-файл** (около 40 MB), внутри он делится сверху вниз на четыре слоя:

| Область | Содержимое |
| --- | --- |
| `<style id="embedded-fonts">` внутри `<head>` | 3 блока `@font-face` (HarmonyOS Sans SC 400/500/700 + Material Symbols Rounded), встроены в base64, `font-display:swap` |
| Основной `<style>` в `<head>` | Весь CSS: дизайн-токены → стили компонентов → анимации → адаптивность (включая боковую панель слева при `html.landscape`) |
| `<body>` | Каркас приложения: верхняя панель / строка поиска / три наложенных друг на друга контейнера страниц с абсолютным позиционированием / нижняя панель + всплывающие окна (выбор иконки, выбор языка, Toast) |
| `<script>` | Весь JavaScript (около 3800 строк): состояние → утилиты → i18n → тема/макет → рендеринг → формы → обмен данными → настройки → запуск |

### 🔀 Поток данных

Гибридная модель **«централизованное состояние + функции рендеринга + прямая работа с DOM в анимациях»**:

```text
Взаимодействие пользователя
   │
   ├── Изменение данных ──→ Store.save() (сохранение в localStorage)
   │                   └──→ Явный вызов renderXxx() для повторного рендеринга нужной области
   │
   └── Чисто визуальное изменение (отметка, перелистывание, волна) ──→ прямая работа с DOM / инлайн-стилями (без повторного рендеринга)
```

> [!WARNING]
> Любое изменение состояния, связанное с анимацией, должно **напрямую работать с DOM** — не запускайте полный повторный рендеринг.

### 🗂️ Модель состояния

Хранится в `localStorage` под ключом `checklist_app_state_v1`:

```js
state = {
  checklists: [
    { id, name, icon, resetHours,          // icon: 'auto' | имя иконки
      items: [{ id, text, icon, done }],
      completedAt, createdAt }
  ],
  activeChecklistId: id | null,
  settings: {
    theme: 'auto' | 'light' | 'dark',
    itemHeight: 64,        // 56~120
    firstOnly: false,      // пользовательская высота применяется только к первому пункту
    language: 'auto' | 'zh-CN' | 'zh-TW' | 'en' | 'ja' | 'ko' | 'fr' | 'de' | 'es' | 'ru' | 'pt'
  }
}
```

Временное состояние (не сохраняется) живёт в переменных уровня модуля: `currentPage`, `formMode` (`'new'|'edit'`), `formState`, `settingsFromPage`, `titleFlipDir`, `titleAnimToken`, `switchAnimToken`, `currentHomeView` и т. д.

## 🚀 Окружение и первые шаги в тестировании

### 📦 Требования к окружению

- Для запуска приложения: любой современный браузер / APK, собранный в HBuilderX;
- Для сборки и тестирования: Node.js ≥ 16 (проект проверен на Node 24); зависимость jsdom входит в `build/node_modules`.

### 🧪 Прогон тестов

```bash
node build/_extract099.js && node --check build/_check099.js   # проверка синтаксиса
node build/_sim099.js                                          # имитация действий пользователя (73 проверки)
node build/_smoke099.js && node build/_smoke099b.js            # регрессионные тесты
```

Все команды должны вывести `ALL PASS` и `uncaught errors: 0` — только тогда тест считается пройденным.

## 🛠️ Конвейер сборки и рабочий процесс разработки

### 🔁 Конвейер патчей версий

Обновление версии — это применение Node-скриптов патчей к HTML предыдущей версии. `apply(old, new, count)` внутри каждого скрипта проверяет число совпадений и прерывает запись при любом несовпадении.

| Скрипт | Назначение |
| --- | --- |
| `upgrade_v09.js` + `patch_v09_css.js` + `keywords_v09.js` + `embed_font_v09.js` + `rebuild_v09.js` | 0.8.0 → 0.9.0 |
| `upgrade_v095.js` / `upgrade_v095b.js` | → 0.9.5 |
| `upgrade_v096.js` / `upgrade_v096b.js` | → 0.9.6 |
| `upgrade_v097.js` | → 0.9.7 |
| `upgrade_v098.js` | → 0.9.8 |
| `upgrade_v099.js` + `upgrade_v099b.js` + `upgrade_v099c.js` + `remove_icons_v099.js` | → 0.9.9 |
| `upgrade_v100.js` | → 1.0.0 |

### ✏️ Как правильно вносить изменения в код

1. Правите HTML нужной версии напрямую (один файл — что видишь, то и получаешь);
2. **Отражайте правки в соответствующем `upgrade_vXXX.js`** (чтобы из старой версии всё пересобиралось одной командой);
3. Коммитьте только после того, как проверка синтаксиса и симуляция/регрессия полностью «зелёные».

### 🎛️ Добавление и удаление иконок и ключевых слов

- Библиотека иконок: `ICON_LIBRARY` (ключи категорий `daily / travel / shopping / sports / leisure / food / health / work / other`);
- Добавление иконки: добавить имя иконки в массив категории → добавить `[icon, {язык: 'ключевое_слово|ключевое_слово'}]` в `build/keywords_v09.js` → пересобрать блок `AUTO_ICON_KEYWORDS`;
- Удаление иконки: удалить её из библиотеки и из данных ключевых слов, затем пересобрать (см. `remove_icons_v099.js`);
- Проверка: не менее 200 ключевых слов на каждый язык; имя иконки должно существовать во встроенном шрифте и в `ICON_LIBRARY`.

### 🌍 Добавление языка

Добавить словарь в `I18N` (набор ключей тот же, что у остальных языков) → зарегистрировать в `LANGUAGES` → довести ключевые слова до ≥ 200 → `getLang()` (auto → точное совпадение → совпадение по префиксу → откат на zh-CN).

## 🧩 Подробное устройство кода

### 🎨 Дизайн-токены и слои CSS

```css
:root{
  --brand-1:#10172F; --brand-2:#283558; --brand-3:#525288; --brand-4:#A5A8BA;  /* четыре фирменных цвета */
  --md-primary:#525288; --md-primary-container:#E1E0FF; …                         /* производная палитра MD3 */
  --md-easing-standard / emphasized / accelerated / decelerated;                  /* токены движения */
  --md-dur-short:150ms; --md-dur-medium:250ms; --md-dur-long:400ms;
}
```

Слои CSS: сброс → шрифты → токены → движение → каркас → верхняя панель → контейнеры страниц → пункты списка → нижняя панель → кнопки/FAB → формы → поиск → настройки → всплывающие окна/Toast → адаптивность. Тёмная тема реализована переопределением переменных через `[data-theme="dark"]`; все изменения цвета плавно переходят через `*{transition-property:…;transition-duration:.25s}`.

### ✨ Система анимаций

- **Паттерн «токен прерывания»**: все прерываемые анимации (перелистывание, заголовок, прокрутка, замена иконок) держат возрастающий токен; колбэки по таймеру сначала проверяют токен и тихо завершаются, если их прервала новая анимация;
- **Перелистывание/переключение**: старый контент за 150ms с ускорением выезжает на 40px + затухает → новый контент с противоположной стороны за 300ms с замедлением въезжает на 40px (одинаково в `switchPage` и `switchChecklist`);
- **Переворот заголовка**: весь заголовок за 140ms выворачивается наружу → за 240ms с замедлением возвращается; направление задаёт направление перелистывания (вперёд — вверх, назад — вниз);
- **Кофейная страница**: появление/исчезновение — через `@keyframes` (надёжно на Android); при переключении чек-листа трактуется как «особый пункт списка» и перелистывается вместе с областью прокрутки (путь `instant` отключает его собственную анимацию);
- **FLIP**: при завершении пункта списка высота схлопывается за счёт CSS transition, без полного повторного рендеринга.

## 📱 Сборка APK (HBuilderX)

### 📦 Шаги

Создать новый проект 5+ App (имя пакета `com.crazysue.checklist`) → положить HTML как входную страницу → отредактировать manifest.json → облачная/локальная сборка → сертификат → собрать пакет.

### 🔌 Используемые plus API

| API | Назначение |
| --- | --- |
| `plus.io.requestFileSystem(plus.io.PRIVATE_DOC, …)` | Экспорт .checklist в приватный каталог приложения (**не возвращайтесь к схеме с общим каталогом**) |
| `plus.runtime.openURL(url)` | Переход по внешним ссылкам в системном браузере по умолчанию |
| `plus.os.name` | Определение платформы (при импорте на Android фильтр `accept` **не используется**) |

### ⚠️ Список граблей платформы

- У файлового ввода на Android обязательно убирать `accept`, иначе в системном выборе файлов нельзя выбрать ничего;
- Запись в общий каталог Download на Android 10+ (File-пути / MediaStore / SAF) на некоторых устройствах полностью не работает (файлы по 0 байт) — в v1.0 в итоге вернулись к приватному каталогу приложения;
- `window.open(url,'_blank','noopener')` открывает две вкладки — для внешних ссылок используйте якоря или `plus.runtime.openURL`;
- `scrollTo({behavior:'smooth'})` в старых WebView молча не работает — для кастомной прокрутки используйте rAF + сглаживание с прямой записью в `scrollTop`;
- `screen.orientation` отражает монитор, а не окно — книжную/альбомную ориентацию определяйте только по пропорциям самого окна;
- Ключевые анимации появления/исчезновения — через `@keyframes`, а не transition «начальное состояние → переключение класса»;
- inline-block схлопывает ведущие пробелы — суффикс заголовка остаётся inline;
- Убирать волну сразу на pointerup — слишком быстро: после отпускания дайте ей доиграть до конца.

## 🧠 Ключевые технические решения и заметки о граблях

| Тема | Решение | Обоснование |
| --- | --- | --- |
| Модель направления страниц | Страницы создания/настроек всегда въезжают справа; страницы чек-листа — слева; при «назад» из настроек на страницу создания направление меняется на обратное | Соответствует ментальной модели пользователя |
| Конечное состояние анимации заголовка | Весь заголовок (имя + «Чек-лист») переворачивается вверх/вниз целиком, применяется на всех страницах | Ранняя двухдорожечная схема «переворот имени + движение суффикса» снова и снова давала телепорты и наложения |
| Кофейная страница | При переключении перелистывается вместе с областью прокрутки; при сбросе уезжает вниз и затухает | Единое ощущение перелистывания |
| Автоматическая пустая строка | В конце всегда есть автоматическая строка без кнопки удаления; при очистке предыдущего пункта она удаляется с анимацией; очистка первого пункта ничего не удаляет | Баланс между удобством ввода и «отсутствием невидимых кнопок» |
| Экспорт | Приватный каталог приложения (APK) / скачивание через якорь (Web) | Надёжно на разных версиях Android |
| Ключевые слова иконок | 630+ слов на язык, приоритет текущего языка с откатом на английский, для западных языков — совпадение по целому слову | Баланс между точностью попаданий и ложными срабатываниями |

## 🧪 Руководство по тестированию

### 🧰 Инструментарий

- **jsdom**: перед загрузкой HTML вырезает base64-ресурсы для скорости; `beforeParse` внедряет сид состояния и polyfill (`scrollIntoView`/`matchMedia`/`URL.createObjectURL` и т. д.);
- **`_sim099.js`**: имитация поведения — реальные DOM-события прогоняют полные пользовательские сценарии, а промежуточные состояния анимаций сэмплируются для проверки таймингов;
- **`_smoke099.js` / `_smoke099b.js`**: функциональная регрессия + проверка кода на уровне строк.

### 📝 Пример имитационного сценария

```js
// beforeParse: сид состояния + мок геометрии макета
window.localStorage.setItem('checklist_app_state_v1', JSON.stringify(state));
window.Element.prototype.getBoundingClientRect = function(){ /* возвращать по необходимости */ };
// реальные события + проверки промежуточных состояний
input.focus(); input.value='пить воду';
input.dispatchEvent(new w.Event('input', {bubbles:true}));
await sleep(60); check('пустая строка исчезает с анимацией', !!document.querySelector('.form-item.removing'));
```

## 🎨 Краткая справка по дизайн-спецификации (MD3)

- Четыре фирменных цвета: `#10172F` `#283558` `#525288` `#A5A8BA`; светлая тема выводится из сида `#525288`, тёмная — из `#283558`;
- Слои состояний: hover 8% / active 12% прозрачного чёрного;
- Шрифт: HarmonyOS Sans SC (400/500/700, **не делайте подмножество** — пользовательский контент может содержать любые иероглифы);
- Иконки: Material Symbols Rounded (вариативный шрифт, `font-variation-settings` управляет FILL/wght), обязательно с Google Fonts;
- Движение: разрешены только переворот-въезд/появление/волна/масштабирование; появление и исчезновение «из ниоткуда» запрещены; сглаживание и длительности — только через токены;
- Переключатель: спецификация 0.8.0 (выкл 12px / вкл 24px), без растяжения при нажатии, нелинейный переход emphasized.
